# CPU を学習で強くする — 設計

Google Colab で CPU (brain) のダウト判断を学習させる仕組みの設計と使い方です。
第 1 段階 (嘘判定モデル) は実装済みで、第 2・第 3 段階は設計のみです。

## 1. いまの弱点

**8 切りを連打されてもダウトしない。**
親番のたびに不要な札 1 枚を「8」と言い張るボット (`pro8`) を、brain 3 人の卓に入れて測りました。

| 卓 | `pro8` の 8 の嘘を見抜けた割合 |
|---|---|
| brain ×3 + pro8 (4人戦) | 27% |
| brain + pro8 (1対1) | 13.5%(1局あたり約 11 回嘘をつかれている) |

**原因** — 手作りの嘘判定は次の掛け算になっています。

```
嘘のオッズ = 状況ごとの基準嘘率 × 自分の手札から分かる証拠 × 相手ごとの嘘つき度
```

この掛け算には、次の 3 つの穴があります。

1. **証拠が増えない。** ダウトされずに通った宣言は「公開情報」として全員が数えます。
   同じ人が 8 を 5 回言っても「公開情報だけで見た確率」と「自分の情報込みの確率」が一緒に下がるだけで、
   両者の比 (= 証拠) はほぼ 1 のままです。
2. **嘘率が上がらない。** 嘘率は「親番で効果札」の基準値 (約 24%) にとどまり、
   ダウトの損益分岐点 (約 55%) に届きません。
3. **相手の嘘つき度が更新されない。** 嘘つき度はダウトの結果からしか更新されません。
   そのため、誰もダウトしない相手の嘘つき度はいつまでも初期値のままです。

つまり、手作りのモデルは**設計者が想定した嘘のつき方しか見抜けません**。
これを、自己対戦のデータから学習したモデルに置き換えます。

## 2. 方針

- **ルールの実装は TypeScript のゲームエンジン 1 つだけ。**
  以前の `server/rl/` は Python でゲームを作り直していました(`env.py` など)。
  そのため、ルールが本物と食い違ったまま学習していました。今回は本物のエンジンをシミュレータとして使い、
  Python は「データを受け取って学習するだけ」にします。
- **推論は依存なしの TypeScript。** モデルは小さな多層パーセプトロンです。重みを JSON で配布し、
  サーバーでもシミュレータでも同じコード (`learnedDoubt.ts`) で同期的に計算します
  (ONNX ランタイム不要。1 回の推論は 0.1 ms 程度)。
- **特徴量の計算は 1 か所。** 学習データの生成と本番の推論が同じ関数 (`doubtFeatures.ts`) を通ります。
  特徴量を変えたら版番号を上げ、古いモデルは自動で無視されます。
- **段階的に進める。**

| 段階 | 学習するもの | 方法 | 状態 |
|---|---|---|---|
| 1 | 嘘判定 P(嘘 \| 観察者の情報) | 教師あり学習 (正解ラベルはシミュレータが知っている) | 実装済み |
| 2 | 出し方 (どの数字を何枚、嘘をつくか) | 自己対戦の強化学習 | 設計のみ |
| 3 | 付け込まれにくさの自動化 | 最善応答ボットを学習してリーグに追加 | 設計のみ |

## 3. 第 1 段階 — 嘘判定モデル (実装済み)

### 3.1 何を学習するか

ダウトの判断は「嘘の確率 p」と「損益分岐点 τ」の比較で決まります。

- **τ は今までどおり計算で求めます。** 当たったときの得 (押し付けられる枚数・効果を止める価値・上がりを止める価値) と、
  外れたときの損 (ライフ・押し付けられる枚数) から決めます。
- **学習するのは p だけです。**

p の学習は教師あり学習です。理由は次のとおりです。

- **正解が分かる。** シミュレータは場の札の中身を知っているので、「本当に嘘だったか」がそのまま正解ラベルになります。
- **報酬の設計がいらない。** 「どの行動が勝ちにつながったか」の割り振りも不要です。
- **データが多い。** 1 局で約 55 件(ダウトできる場面 × ダウトできる人数)取れます。
- **安定している。** 強化学習よりずっと安定し、少ないデータで済みます。

### 3.2 入力 (114 次元)

`server/src/game/brain/doubtFeatures.ts` で作ります。観察者がルール上知ってよい情報だけを使います。

| グループ | 内容 |
|---|---|
| 宣言 | ランク (14)、枚数、カウンターか、親番か、上がりか、効果札か、禁止上がりか、宣言前後の手札枚数 |
| ルール | 革命・11 バック・強さの逆転、Q ボンバー有効か、人数、自分が次の手番か |
| 自分 | 宣言ランクとジョーカーの所持枚数、手札枚数、ライフ |
| 公開情報 | 表向きの枚数、これまでに通った宣言の枚数、所在不明の枚数、「通った宣言が残り枚数を超えている量」 |
| 手作りモデル | 正直に出せる確率 (自分込み / 公開のみ)、証拠比、手作りの嘘確率、損益分岐点 |
| **宣言した人の履歴** | 宣言回数、**同じランクの宣言枚数・連続回数**、効果札の宣言回数、ダウトされた結果、自分が渡した札 |
| 卓の傾向 | もっともらしさ別の嘘率・ダウト率 |
| 全体像 | ランク別の自分の手札・表向き・通った宣言 (14 × 3) |

**宣言した人の履歴**の列が今回の要です。たとえば「この人はさっきから 8 ばかり言っている」は、
同じランクの連続回数と宣言枚数から読み取れます。

### 3.3 データ — リーグ自己対戦

嘘の確率は「相手がどういう打ち手か」で変わります。そこで、毎局ランダムに選んだ打ち手で卓を組みます
(`server/sim/gen-doubt-data.ts` の `LEAGUES`)。

| 打ち手 | 中身 |
|---|---|
| `brain` / `brain:heuristic` / `brain:bold` / `brain:timid` | 本番の CPU (学習モデルあり / なし / 嘘多め / 嘘少なめ) |
| `pro8` / `pro10` | brain の打ち方 + 親番で毎回 8 / 10 を言い張る (上級者の付け込みの再現) |
| `spam8` / `spam10` / `spamJoker` / `liar` / `sneaky` | 単純な嘘の繰り返し (`sim/exploiters.ts`) |
| `legacy` / `random` | 従来の CPU / ほぼランダム |

搾取型を混ぜるのは、**対局中に相手の癖を見抜く力**を学ばせるためです。
素直な打ち手しかいないデータで学習すると、「1 回目の 8 は 24% 嘘」は学べても、
「同じ人の 4 回目の 8 はほぼ嘘」は学べません。

規模の目安は次のとおりです(ローカルの測定)。

- **速度:** 1 プロセスで約 170 局/秒です(学習モデルを使う第 1 世代以降は約 70 局/秒)。
- **行数:** 1 局で約 55 行です。
- **容量:** 1 行あたり 456 バイトなので、100 万行で約 0.46 GB です。
- **Colab の場合:** 2 コアの無料ランタイムなら、1 世代 (約 1 万 5 千局 → 約 80 万行) を約 1 分で作れます。

### 3.4 モデルと学習

`server/learn/train_doubt.py` で学習します。

- **構成:** 114 → 256 → 128 → 1 の多層パーセプトロン(ReLU・ドロップアウト 0.1)で、二値交差エントロピーを最小化します。
- **最適化:** AdamW と OneCycle 学習率を使い、検証損失が最小のエポックの重みを残します。
- **検証データの分け方:** 対局単位で分けます(同じ宣言を複数人が見た行が学習と検証にまたがらないように)。
- **確率の較正:** 最後に検証データで温度スケーリングをし、確率を較正します(最終層に畳み込むので、推論側の変更は不要)。
- **書き出し:** 重み・正規化値・特徴量名・版番号を JSON に書き出します(約 0.5 MB)。

### 3.5 世代の反復

モデルを持った CPU は嘘を見抜くようになります。すると、嘘をつく側(同じ brain)の振る舞いも変わります
(ダウトされやすくなったと学んで嘘を控える)。そこで世代を回します。

1. **第 0 世代:** 手作りの判定だけで打つ卓でデータを作り、学習します。
2. **第 1 世代:** 第 0 世代のモデルを持った CPU の卓でデータを作り直し、直近 2 世代ぶんのデータで学習し直します。
3. **第 2 世代以降:** 同じことを繰り返します(`self` リーグ = 本番に近い brain 同士の卓も混ぜる)。

### 3.6 評価と合格基準

評価は 2 通りで行います。

**学習スクリプトのレポート(検証データ)**

| 項目 | 内容 |
|---|---|
| logloss / AUC | 手作りモデルと比べる |
| edge | 「p > τ のときダウトした場合の損得の平均」。ダウト判断そのものの良さを表す |
| 打ち手別 catch / false | 嘘を見抜けた割合と、本当なのに疑った割合 |

**シミュレータの対戦(`node dist-sim/sim/arena.js`)**

| 卓 | 見るところ |
|---|---|
| `brain ×3 + pro8` | pro8 の嘘を見抜けた割合 (`caught%`) と pro8 の順位点 |
| `brain, brain:heuristic` ×2 | 学習モデルありの brain が、なしより強いか (順位点 > 0.5) |

**合格の目安**

- **8 切り連打を見抜く:** `pro8` の `caught%` が 60% 以上で、pro8 の順位点が brain より明確に低い。
- **普段の強さを落とさない:** brain 同士の普段の対局で、学習モデルありが手作り判定より弱くならない。

### 3.7 ローカルでの試行結果

ローカルで 2 世代ぶん回しました(約 160 万行、PyTorch の CPU 版で学習 1 分程度)。
その結果のモデルを `server/models/doubt-model.json` に置いてあります。

**検証データでの比較**

| | logloss | AUC | edge |
|---|---|---|---|
| 学習モデル (第 1 世代) | 0.356 | 0.920 | 137 |
| 手作りの判定 | 0.775 | 0.589 | 31 |

**8 切り連打への対応(シミュレータの対戦、2000 局)**

| 卓 | pro8 の嘘を見抜けた割合 | pro8 の順位点 |
|---|---|---|
| 手作りの判定 ×3 + pro8 | 27% | 0.47 |
| 学習モデル ×3 + pro8 | 83% | 0.10 |
| 学習モデル + pro8 (1対1) | 85% | 0.02 (brain の勝率 98%) |

**普段の強さ**

- 学習モデルありの brain と手作り判定の brain を 2 人ずつで対戦させると、順位点は 0.547 対 0.455 でした(学習モデルありが上)。
- 従来 CPU 3 人が相手のときの順位点は、学習モデルなしの 0.937 から 0.951 に上がりました。

**課題**

本当なのに疑ってしまう割合は 9〜19% です(手作りの判定は 6〜32%)。特に `random` 相手で高めなので、
Colab でデータを増やして下げるのが次の目標です。

### 3.8 配布

- **置き場所:** `server/models/doubt-model.json` に置くと、サーバーとシミュレータが起動時に自動で読み込みます。
- **切り替え:** 環境変数 `DOUBT_ROYALE_DOUBT_MODEL` で別のファイルを指定できます(`off` で無効)。
- **安全策:** ファイルが無い、壊れている、特徴量の版が合わない、のいずれかの場合は手作りの判定に戻ります。

## 4. 第 2 段階 — 出し方の学習 (設計のみ)

嘘判定が強くなると、今度は「いつ・何を・何枚で嘘をつくか」の価値が変わります。
出し方も学習で最適化します。

### 4.1 行動の表し方

brain が列挙する候補手(正直な手・嘘の手・パス)を、そのまま行動の候補にします。
ネットワークは「盤面の特徴 + 候補手の特徴」から候補ごとのスコアを出し、ソフトマックスで方策にします。
合法手だけが候補に並ぶので、反則手の心配がありません。

### 4.2 学習方法(第一候補: ロールアウトによる方策改善)

1. 自己対戦の各手番で、候補手ごとに、見えない手札をランダムに配り直した対局を最後まで K 回進めます
   (エンジンが 1 局 3 ms と速いのでできる)。そして平均の順位点を求めます。
2. その値を目標に、候補手の価値ネットワークを回帰で学習します(教師あり)。
3. 学習した価値で手を選ぶ CPU で、1 に戻ります。

PPO などの方策勾配法より安定し、Node で自己対戦・PyTorch で学習という今の分担のまま実現できます。
ロールアウトのコストが高すぎる場合は、PPO(Node が ONNX 不要の TS 推論で対局を生成し、PyTorch で更新)に切り替えます。

### 4.3 報酬

最終順位の順位点です(1 位 = 1、最下位 = 0、脱落 = 0)。

### 4.4 相手

第 1 段階の最新の嘘判定モデルを持つ CPU を含むリーグにします。

## 5. 第 3 段階 — 付け込まれにくさの自動化 (設計のみ)

今は搾取型ボットを手で書いています(`sim/exploiters.ts`)。これを自動化します。

1. **最善応答ボットを作る。** 最新の嘘判定モデルを固定し、それに対して最も得をする嘘のつき方を
   第 2 段階の仕組みで学習します。
2. **リーグに加える。** そのボットをリーグに加え、嘘判定モデルを学習し直します。
3. **繰り返す。** 1 と 2 を繰り返します(PSRO と呼ばれる方法の簡易版)。

指標は「最善応答ボットが平均よりどれだけ得をしたか」(= 付け込まれやすさ)で、0 に近いほど良いです。

## 6. Colab での手順

1. `server/learn/doubt_royale_colab.ipynb` を Colab で開きます。
   GitHub から開くか、ファイルをアップロードします。
2. 最初のセルで `GENERATIONS` と `GAMES_PER_WORKER` を決めて、上から順に実行します。
   - **非公開リポジトリの場合:** Colab のシークレットに `GITHUB_TOKEN` を登録します。
   - **ドライブへの保存:** `SAVE_TO_DRIVE = True` にすると、世代ごとのモデルをドライブにも保存します。
3. 各世代のあとに、評価の対戦結果が表示されます。
4. 最後のセルで `doubt-model.json` がダウンロードされます。
   それを `server/models/doubt-model.json` に置いてコミットします。

ローカルで同じことをする場合(server ディレクトリで実行):

```bash
npx ts-node -T sim/gen-doubt-data.ts --games 6000 --out learn/data/gen0/w0 --no-model
```

```bash
python learn/train_doubt.py --data learn/data/gen0 --out models/doubt-model.json
```

```bash
npx ts-node -T sim/arena.ts --games 2000 --seats brain,brain,brain,pro8
```

## 8. 旧 `server/rl/` について

DQN / PPO / DeepNash 風の学習スクリプトと ONNX モデルが残っています。
ただし、どれも本物と異なる Python 版のゲームで学習しています。CPU は既定ではこれらを使いません
(`DOUBT_ROYALE_USE_MODEL=true` のときだけ)。新しい仕組みが定着したら削除してかまいません。
